## 背景

当前设置页只包含模型、推荐行为和开发模式配置，没有公开反馈入口。项目已经以 GitHub Issues 作为缺陷入口，因此无需新增表单、账号或服务端。

## 目标与非目标

**目标：**

- 让用户可以从设置页一键进入项目反馈渠道。
- 入口跟随插件界面语言，并明确会打开 GitHub。
- 保持反馈行为由用户显式触发，不自动附带本地数据。

**非目标：**

- 不实现应用内反馈表单、匿名统计或自动上传日志。
- 不预填 Vault 内容、API key、API 地址或模型名。

## 决策

- 在设置页末尾使用 Obsidian 原生 `Setting` 和按钮组件，保持与现有设置项一致。
- 点击按钮时通过 `window.open` 打开仓库的 GitHub 新建 Issue 页面，并使用新标签页及 `noopener,noreferrer` 限制 opener 访问。
- 将按钮名称和说明纳入现有 `LabelTree`，同时维护中英文文案。
- 在已有设置页端到端测试中验证按钮可发现，并验证点击目标 URL 和窗口参数。

## 风险与取舍

- GitHub 账号门槛可能阻止部分用户提交反馈 -> 文案明确反馈渠道，后续根据实际需求再评估其他渠道。
- 外部页面结构或仓库地址可能变化 -> 将 URL 定义为设置模块中的单一常量，并由测试约束。
