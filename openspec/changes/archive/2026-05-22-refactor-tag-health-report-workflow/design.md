## 背景

现有健康报告同时承担四件事：

1. 展示规则检测出的标签问题。
2. 触发并展示 AI 增强分析。
3. 展示清理动作能力和文件预览。
4. 提供可执行项的应用/回退入口。

这些能力本身都需要，但它们现在被平铺在一个长报告中，导致用户看不出主次。尤其是 AI 增强分析和规则分析都使用类似的标签、优先级、置信度、问题类型，容易形成“两个报告互相重复”的感觉。

## 目标 / 非目标

**目标：**

- 建立清晰的信息层级：总览、AI 行动层、规则证据层。
- 初始态明确说明：规则分析已经完成，AI 需要用户主动触发。
- AI 分析中不阻塞整个报告，用户仍可查看规则证据。
- AI 结果不再作为平行报告展示，而是作为“优先处理项”展示。
- 规则明细仍保留六类问题，用于解释证据来源。
- 复用现有动作能力模型，继续保证 AI 不能提升动作可执行性。
- 支持中英文 UI 文案，但 OpenSpec 文档使用中文。

**非目标：**

- 重写规则分析算法。
- 重写 AI prompt 的全部能力边界。
- 引入新的批量执行能力。
- 修改 inline tags 写入边界。
- 改变插件命令名称或设置项。

## 信息架构

### 1. 总览层

总览层回答“这个库整体怎么样”：

- 标签数。
- 标签使用次数。
- 风险分组数。
- 可执行建议数。
- 生成时间和索引时间。
- 一句分工提示：规则是证据层，AI 是行动建议层。

总览层不展示具体标签列表，避免一打开就进入细节噪音。

### 2. AI 辅助行动层

AI 行动层回答“我接下来应该先处理什么”。

它有三个状态：

1. **初始态**
   - 规则分析已完成。
   - AI 尚未运行。
   - 展示空状态和“生成 AI 辅助分析”按钮。
   - 空状态说明 AI 会合并跨规则问题、排序优先级、补充目标标签与风险提示。

2. **分析中态**
   - 展示非阻塞 loading 区域。
   - 按阶段展示“整理规则证据、合并相关标签问题、生成行动建议与风险提示”。
   - 用户仍可查看下方规则证据明细。
   - 开发模式下继续展示总耗时和阶段耗时。

3. **结果态**
   - 展示 AI 聚合后的优先处理项。
   - 每个处理项可以关联多个规则问题类型。
   - 每个处理项展示标签、优先级、置信度、动作能力、诊断、建议动作、规则证据来源、按钮。
   - 只有本地动作能力为 `executable` 的项目展示“应用”按钮。
   - `observeOnly` 和 `manualReview` 只展示“复制计划”或“查看证据”。

### 3. 规则证据层

规则证据层回答“系统发现了什么证据”。

它继续使用六个底层分类：

- 低频标签。
- 近似重复。
- 过宽标签。
- 过细标签。
- 层级不一致。
- 命名风格不一致。

展示方式改为紧凑 tab 或 segmented control。每次只突出一个分类，避免六类全部铺开。

规则证据层必须明确说明：规则明细只说明发现了什么，不直接代表必须处理。

## AI 与规则分工

规则分析负责：

- 统计标签出现次数、文件数和层级深度。
- 发现低频、重复、过宽、过细、层级不一致和命名风格不一致。
- 生成文件级预览。
- 生成 cleanup plan。
- 决定动作能力和可执行性。

AI 辅助分析负责：

- 合并多个规则分类下的同一主题问题。
- 判断优先级和置信度。
- 解释为什么某组标签值得优先处理。
- 提供候选目标标签和风险提示。
- 标记哪些规则问题可以继续观察。

AI 不能：

- 创建不存在于本地规则证据中的执行权限。
- 把 `observeOnly` 或 `manualReview` 升级成 `executable`。
- 绕过文件预览、操作日志和撤销要求。
- 直接决定 Markdown 写入。

## 数据组合策略

实现时可以增加一个只服务 UI 的 view model，例如：

```ts
interface HealthActionItemView {
  id: string;
  tags: string[];
  priority: "high" | "medium" | "low";
  confidence: "high" | "medium" | "low";
  diagnosis: string;
  suggestedAction: string;
  evidenceTypes: TagHealthIssueType[];
  cleanupItem?: CleanupPlanItem;
  source: "ai" | "ruleFallback";
}
```

组合原则：

- AI 已运行时，优先使用 AI priorities 生成行动项。
- AI priority 通过 issue type 和 tags 匹配 cleanup plan item。
- 匹配到 cleanup item 时，行动项继承本地 action capability。
- 未匹配到 cleanup item 时，行动项只能展示为人工判断，不展示应用按钮。
- AI 未运行时，不生成“优先处理项”，只展示初始态说明。
- 规则明细始终来自 `TagHealthReport.sections`，不被 AI 改写。

## 风险 / 权衡

- [风险] 把优先处理项放在主视图，可能让用户忽略规则证据。-> 缓解：每个行动项展示规则证据来源，并提供规则明细 tab。
- [风险] AI 没运行时页面显得“空”。-> 缓解：初始态清楚说明规则分析已完成，并直接展示规则证据明细。
- [风险] 当前 AI 输出结构可能不足以表达多个规则证据来源。-> 缓解：第一版可以通过 tags 和 issueType 匹配 cleanup plan；后续再扩展 AI schema。
- [风险] modal 文件继续膨胀。-> 缓解：实现时应优先拆出纯 view model 和小渲染方法，必要时新增 `HealthReportViewModel.ts`。
