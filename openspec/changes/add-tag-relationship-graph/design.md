## Context

用户希望查看 tag 与 tag 的关系。本方案基于 0.5.0 / `6647123` 的实际源码；[research.md](research.md) 保存外部资料和源码依据。当前 `TagIndex` 已足够计算精确共现，`TagIndexService` 已维护新鲜度；工作台和索引规格尚在已实现的 `add-tag-management-workbench` change 中，不能把 `openspec/project.md` 的旧“下一阶段”描述当作当前实现状态。

新增能力仅消费只读快照。已有保护策略、操作历史、写入审查和恢复链路不因打开关系图而发生变化。

## Goals / Non-Goals

**Goals:**

- 让用户比较标签实际使用范围，检查共同/各自独有的笔记，再决定是否进入已有整理审查。
- 默认从标签搜索或当前标签的一跳邻域开始；提供可选有限概览，明确过滤与显示截断。
- 在关系探索与管理审查之间保留只读标签对上下文，支持取消返回、操作后核对及已有撤销入口。
- 区分共现和语法层级，支持中英文、深浅主题、键盘及窄窗口。
- 在计算、刷新、失败与取消期间保留可用界面，确保派生结果与来源版本一致。

**Non-Goals:**

- 不增加标签写入、图内合并/改名、自动清理、语义推断或全库无上限布局。
- 不改造原生 Graph，不依赖其私有 renderer，不读取正文生成关系，不新增 AI/网络请求。
- 不增加图谱导出、布局持久化、后台自动扫描、持续物理动画、聚类或移动端图谱验收。

## Decisions

### D1. 独立只读关系模型，复用索引语义

新增模块职责如下，文件名可在实现中微调，依赖方向保持不变：

| 模块 | 职责 |
| --- | --- |
| `TagRelationshipModel` / `TagRelationshipBuilder` | 规范化身份、范围/来源投影、候选选择、精确边权、层级边与证据 |
| `TagGraphService` | 捕获版本、准备最小快照、启动/取消任务、提交完整结果、保留有效结果 |
| `tag-graph.worker` | 关系计算与静态力导向布局；不依赖 Obsidian API、DOM、文件系统或网络 |
| `TagGraphPanel` / `TagGraphRenderer` | 稳定 SVG 容器、缩放、选择和详情；不修改领域数据 |
| `TagRelationshipTable` | 等价的可访问分页关系表，Worker 不可用时仍可浏览关系证据 |

`TagManagementAdapter` 增加只读图谱服务接口与完整索引版本元数据。图谱服务只接收 index、scope、policy 和文件打开能力，不接收 `startManual`、undo 或持久化操作日志能力。

工作台协调层单独接收导航事件，维护 `TagRelationshipContext`：精确 A/B、已应用查询、快照身份、当前证据分组/页码、根和返回位置。它只引用同一份只读比较结果，不复制所有文件路径、不创建 mutation intent。进入手动操作仍由已有管理入口构造新 intent；服务与渲染器不通过导航回调间接执行写入。

快照剔除 `examples`、`snippet`、笔记正文及所有 provider/操作数据。关系身份使用现有 `normalizeTag`；tag/path 使用整数表和 `Map`，不将不可信标签直接作为对象原型键、DOM id 或 CSS 选择器。显示标签通过文本节点，边 id 采用类型与整数端点编码。

### D2. 文件集合是唯一计数依据

对查询 Q，定义 `F_Q(t)` 为：在管理 scope 内、未被全局排除、且精确标签 t 的来源满足 Q 的去重文件集合。来源选项为“全部 / 属性 / 正文”；全部保留 metadata-only 证据，属性/正文只能匹配对应明确来源，不能猜测 legacy metadata 的来源。来源过滤同时作用于边的两端。

- 节点大小取 `sqrt(|F_Q(t)|)` 的有界映射，详情显示真实文件数。
- 共现为无向边，`shared=|F_Q(a)∩F_Q(b)|`，同文件重复 token 或多来源只贡献一次；不生成自环。
- `J=shared/(|F_Q(a)|+|F_Q(b)|-shared)`；只对 shared>0 的边展示，显示为“交并比”，不写“语义相似度”。
- 标签对比较另计算 `onlyA=F_Q(a)\\F_Q(b)`、`onlyB=F_Q(b)\\F_Q(a)`、`coverageA=shared/|F_Q(a)|`、`coverageB=shared/|F_Q(b)|`。界面写明“A 的笔记同时含 B 的比例”和反向比例，不把覆盖率命名为合并置信度。
- 共现边默认 `shared>=2`，用户可设正整数阈值，包括 1；按 shared 降序、J 降序、规范化端点键升序稳定排序。
- 节点详情每页 50 个 `F_Q(t)` 文件；比较详情的共同/仅 A/仅 B 三组各自按规范化库相对路径分页，每页 50；不使用宿主含后代的标签搜索作证据。
- 比较可从共现边进入，也可从完整范围搜索独立选择两个不同标签，不受图节点上限或共现阈值限制。两者有成员且交集为零时，J 和覆盖率均为 0，差集完整展示；不创建零权重图边。规范化后 A=B 时提示选择不同标签；端点不在查询中时显示不可用，零分母显示不适用，不伪造 0%。
- 不为每条边复制所有路径。保留本次候选及当前比较端点的有序 file-id 集合，详情按需求交/差分页；比较不扩大图候选、不中途替换已应用查询，仍受同一预算、取消和版本校验约束。

来源选择只控制浏览统计，不能传递为写入授权。图谱来源为 inline 而索引配置未读取 inline 时，显示该来源不可用及设置入口，不把“未采集”显示成“没有关系”。

### D3. 层级边只表达已有标签的直接语法父子

层级叠加默认关闭。仅当两个选中候选标签分别是 `a` 与 `a/b` 时生成 `a→a/b`，中间只差一个路径段；`a` 与 `a/b/c` 不跨越缺失的 `a/b` 连边。父标签必须自身有 `F_Q(a)` 文件，不能从后代虚构父节点或累计父文件数。

层级用有向虚线，共现用无向实线，图例及关系表均显示类型。同一对节点可有两种边，使用可区分的平行线/命中区域。层级边不带共同文件数/Jaccard；详情说明命名关系并允许分别查看父、子文件，不能伪造共同文件证据。其存在不受 shared 阈值影响。

### D4. 候选限制先于成对枚举，计数仍精确

用户显式选择概览后，对 Q 下所有标签先计算文件数，再按文件数降序、规范化键升序取前 N；N 可选 50/100/200，概览默认 200。首次独立打开不自动生成概览。只有这组候选之间计算共现，限制的是展示范围，**不是**对文件采样。每条已显示边仍包含当前查询全部匹配文件。

搜索不是先过滤概览前 200：它查询 Q 下完整标签集合，采用字面子串、分页结果，选择任意标签可进入邻域。邻域将该标签固定为根，计算它与所有其他合格标签的共现，按 shared/J/键排序取最多 49 个达阈值邻居，再计算候选之间的边。根本身无邻居时仍显示，说明当前阈值下无共现；邻域不递归扩展。层级叠加只作用于已经选出的节点，不额外扩大邻域。

总可见边上限 800。开启层级时先保留候选间全部直接层级边（200 个节点最多 199 条），其余额度按稳定排序保留共现边。首版保留候选孤立点，文案为“当前显示范围/阈值下无连线”，不能称为全库孤立标签。

视图展示 Q 的总合格标签数、候选数、可见共现/层级边数、候选内达阈值边总数、隐藏节点数/边数及截断原因。候选外的关系没有计算，因此不得声称知道全库边总数或“全部关系均已展示”。只切换层级显示不会改变共现计数。

替代方案“先为全库所有标签建立所有边再裁剪”在高密度标签笔记上为平方增长，因此不采用；“每篇只取前 k 个标签”会损害计数，禁止采用。

### D5. 工作台集成与可访问流程

新增第三个页签“关系图”，命令 `open-tag-relationship-graph` 打开或复用工作台并选中该页签。首次独立打开显示范围/来源摘要及完整范围的标签搜索/分页列表，选择标签才生成一跳邻域，另有“查看范围概览”入口。标签详情增加“查看关系”，只传精确 tag key，直接生成该标签邻域。图谱详情“在标签列表查看”定位精确标签，不自动选择写入项。

布局顺序为范围/来源摘要、概览/邻域模式与搜索、共同文件阈值和节点数、层级开关、状态行、图/关系表、证据详情。900px 以上图与详情并排；360px 窄窗口使用图/表与详情切换和返回，不能横向挤压控件。

已有索引时搜索入口可用，其投影仍遵守分片规则；没有索引时显示“刷新索引”入口，不能自动扫描。图谱参数的变更显示待应用状态，用户点击“生成关系”后启动新任务；搜索高亮、缩放和平移仅改变展示，不重算统计。选择根、显式打开概览及提交一对比较标签都是生成动作；回概览恢复上次概览参数，返回搜索入口不启动图布局。

键盘可切换三个页签、使用搜索、选择节点/关系、切换三组证据、打开笔记、带入整理及返回；提供放大/缩小/适配视口按钮。关系表每页 50 行，包含关系类型、端点、共现文件数和交并比；与图共享可见边集合和选择状态，另提供节点列表访问无边节点。表和搜索均提供独立比较入口，零共现对不伪装为关系表中的边。图是渐进增强，不能要求用户必须拖拽或分辨颜色才能完成主流程。

比较详情提供“带入整理”，仅切换到标签页并呈现 A/B、查询口径和返回入口组成的只读上下文。它不自动勾选源标签、目标、文件或 occurrence，不预设合并方向，不直接打开写入确认。用户在管理页另行选择改名/合并、源和目标后，复用现有范围确认、预览、保护、冲突检查、日志与撤销；UI 明示浏览来源和三组证据不是实际修改范围。准备审查使用最新有效状态，旧比较快照不能为写入背书。

上下文只在当前工作台会话内保留。取消整理可返回同一比较和有效视口；索引/库变化则标记旧证据过期，重新比较成功后才显示新计数。scope/排除变化立即清除旧数量和路径；端点消失则显示不再可比较，不自动换成父标签或合并目标。操作后使用已有历史查看执行/撤销结果，需更新关系时显式刷新索引；不能把旧图称为整理后结果。关闭视图清除上下文，跨重启保存查询属于后续 TODO。

### D6. 静态 SVG 布局，Worker 内执行计算

按模块引入 `d3-force`、`d3-selection`、`d3-zoom`，不引入完整 d3 包。Worker 克隆节点，调用 `forceSimulation(...).stop()`，以固定排序、固定种子与最多 300 次 tick 计算静态坐标。主线程批量应用坐标；初次布局后不常驻 tick，不因 hover 或主题变化重新布局。视觉位置是布局结果，不额外表达语义。

esbuild 先将 Worker 打为自包含浏览器 IIFE，再以字符串嵌入 `main.js`，使用当前视图 `ownerDocument.defaultView` 的 Worker/Blob/URL 创建运行时。最终发布仍只需要现有三项资产，无 `eval`、远程 import 或运行时 CDN。主窗口、弹出窗口、关闭和重新打开必须检查 Worker、Object URL、ResizeObserver、事件监听及订阅释放。

Worker 不能启动或异常退出时，结束该任务并提供“使用关系表重试”。重试使用同一纯关系算法的异步分片执行器，每片目标不超过 4ms，内部循环具有可恢复游标，切片后交还事件循环；不在 UI 线程运行力导向模拟。关系表保留同样计数、证据、取消和预算，不能回退到长时间同步循环。用户可显式重试图模式；不能无限自动重试。

### D7. 任务、版本与旧结果保留

服务捕获 `indexRevision / vaultRevision / policyRevision / scopeKey / source / queryKey / generation / readInlineTags`。计算输入绑定一个不可变索引引用，查询、策略、设置、版本或 generation 改变均使旧任务不可提交。进度、错误、证据响应与坐标消息同样验证身份。

独立标签对比较将规范化 A/B 和证据分组纳入请求身份；同一视图仍只有一个计算任务，新的比较/图生成取消旧任务并保留同范围已完成结果。单对比较跳过布局和无关标签对枚举，采用精确集合运算；证据分页同样可取消、限时，不允许快速切换 A/B 后混入旧差集。

状态包括 `idle / preparing / counting / layingOut / ready / cancelled / error / limited`；索引的 `missing/ready/stale/refreshing/error` 独立显示。最后索引时间始终来自 `index.updatedAt`，不能被布局或重绘时间覆盖。

- 同 scope/policy 下重算、刷新、取消或失败保留上次有效图、证据和视口；新参数尚未生效时，旧图旁明确显示其旧来源/阈值及“新设置尚未应用”。
- scope 或排除策略变化立即取消、撤销旧图/证据/缓存，不允许旧范围数据在新范围下短暂显示；保护标签仍可只读浏览，不参与图中写入。
- stale 缓存可派生只读图，但必须持续标记“基于过期索引”；外部变更只标脏，不自动扫库或循环重算。文件打开检查当前路径存在，缺失则提示并保留其他证据。
- 索引成功刷新后，可见图谱按当前已应用参数自动重算一次；若页签不可见只标脏，下次进入时生成。布局成功不使过期索引变为最新。
- 关闭视图、切离图页签、取消、替换任务都终止 Worker/分片任务并失效 generation；同一视图同时最多一个任务。切页签保留符合当前范围的已完成图用于返回，关闭视图释放图谱缓存。

全局 `user-action-contract`（`$CODEX_HOME/skills/user-action-contract/SKILL.md`）是异步交互约束来源；实现时按全局技能核验，项目只记录本功能差异：生成状态不复用工作台全局 `pending`，其他页签、搜索、打开笔记和取消仍可操作；旧结果保留不适用于范围或排除策略的失效。

### D8. 预算必须在准备、枚举和显示三个阶段生效

以下为第一版待测门禁，不能当作已测性能：

| 阶段 | 约束 |
| --- | --- |
| 准备输入 | 最多检查 1,000,000 条原始 tag-file membership；最小 DTO 序列化上限 32 MiB；不包含全文/片段 |
| 主线程准备与回退 | 可中断迭代和排序、每片目标 ≤4ms；postMessage 分批最多 4,096 membership，最多两批未确认，不一次克隆完整 TagIndex |
| 精确统计 | 最多 10,000,000 次标签对计数更新（包含邻域根与其他标签的统计）；按游标检查预算，不跳过高密度笔记 |
| 整个生成任务 | 从点击到计算结束最长 10 秒，超限为 limited，保留同范围旧结果并建议缩小 scope；布局 ≤300 ticks 且受同一期限约束 |
| 绘制 | 概览 ≤200 节点/800 边，邻域 ≤50 节点/800 边；SVG 分批创建，完成后原子替换，避免每个进度更新全量重建 |
| 取消 | 250ms 内停止任务/派发；晚到消息永不提交 |

预算触发必须显示具体原因，不能显示部分统计为精确完整结果。切换到关系表解决渲染/Worker 不兼容，不豁免输入/统计预算。

### D9. 验收证据与回归范围

测试先覆盖小型可手算夹具：同文件多来源去重、大小写、精确父子、metadata-only、来源未采集、排除范围、Jaccard 和证据分页。再覆盖确定性候选/截断、低频根邻域、同时两类边、输入顺序变化，以及取消、版本变化、策略清理、错误/晚到结果、Worker 失败、关闭/弹出窗口。

性能夹具至少包括：1,000 标签/1,000 文件/每文件 10 标签；10,000 标签/10,000 文件/每文件 10 标签；稠密 200 标签共同出现于 1,000 文件（应触发计数预算）；超过 1,000,000 原始 membership；零关系及长中文标签。固定种子，记录实际 membership 数、候选/显示规模、硬件、宿主版本、运行方式和 SHA。

目标：前两组预热 5 次、测量 30 次，点击生成至图就绪 p95 分别 ≤2s/≤5s；生成状态在 100ms 内可见；计算期间无关交互 p95 ≤100ms，不出现单次超过 100ms 的图谱主线程长任务；取消 ≤250ms。超预算夹具必须有界停止而非追求出图。分开记录准备、传输、统计、布局、渲染和包体积，失败不得标通过。

真实桌面宿主在最低支持版本 1.8.7 和验收时当前稳定版本执行：断网、无 API key、无活动笔记、冷启动、缓存 stale、刷新失败、生成期间切标签页/打开笔记、弹出窗口、深浅主题、360px/900px、键盘、减少动画及连续打开关闭。额外执行原有手动改名/合并与撤销回归，证明页签改造未破坏已有工作台；不是在图中增加写入。

产品任务另设固定答案夹具：A=100、B=10、共同=10 的范围包含；名称近似但零交集；高频通用标签掩盖低频根；来源过滤导致证据与实际审查范围不同。验证用户能找共同/差集并解释两个覆盖率，不会因共现/包含直接判断同义；带入管理后明确选择操作与范围，取消返回、执行和撤销均可核对。先以现有标签列表为基线，再用同一合成库对测 Tag Lens、AI Tagger Universe、TagFolder 和原型，仅比较各自支持的任务。记录版本、设备、参与者与任务顺序、时间、步骤、判断依据、误判和恢复结果；小样本与未支持项如实保留，不宣称已证明留存或付费价值。

## Risks / Trade-offs

- [高频偏置] → 共同文件数之外展示交并比，允许聚焦任意标签；不声称全库最重要关系。
- [共现被误当同义] → 同时展示差集及双向覆盖率；零共现也允许比较，命名/健康报告证据与使用范围证据分开解释。
- [探索上下文变成写入授权] → 导航只读，管理页重新表达操作意图并审查；数据变化失效旧证据，沿用保护与恢复门禁。
- [有界概览遗漏长尾] → 显示截断原因和总合格标签数，搜索覆盖全部范围标签，局部邻域不受概览前 N 限制。
- [嵌套标签误读] → 精确文件集合与独立层级类型，不累计后代、不创建隐含父节点。
- [UI 订阅重建导致抖动] → 拆分工作台静态 shell 和区域更新，保留图容器和焦点，复用原有列表/历史回归测试。
- [Worker/打包不兼容] → 离线真实宿主前置验证、可取消分片关系表回退，未过宿主门禁不宣称图功能完成。
- [大快照序列化阻塞] → 准备和传输也分片、背压与限额；并非只把布局放入 Worker。
- [移动端差异] → 不改变 `isDesktopOnly:false`，在移动端提供清晰未支持状态和既有标签列表，不能让新增依赖初始化导致整个插件加载失败。

## Migration Plan

1. 完成 Worker/SVG 最小原型和预算基线，再实现模型、服务及工作台集成；原型失败时更新选型证据与设计，不静默改为同步全量计算。
2. 无持久化索引或日志迁移；图谱布局、证据及管理交接上下文只在当前视图内存中保留，旧版本可忽略新增页签状态，默认回到标签页。
3. 打包、离线安装和宿主门禁完成后更新 README/CHANGELOG/路线图，明确来源与规模限制。该设计不预先承诺版本号或发布日期。
4. 回退时撤回图谱入口和新增模块、恢复原发布三件套；无需恢复笔记或操作日志。
