## 2. 外部资料和产品含义

资料访问日期均为 2026-10-28。以下“项目判断”是本项目的推论，不是引用资料给出的性能承诺。

| 来源 | 已核查事实 | 项目判断 |
| --- | --- | --- |
| [Obsidian Graph view](https://obsidian.md/help/plugins/graph) | 原生图以笔记与内部链接为基础，允许显示标签，并提供局部图、过滤、缩放与平移 | 可以借鉴导航习惯；我们要补充的是标签对之间的共同笔记证据，而不是再画一套笔记链接图 |
| [Obsidian Tags](https://obsidian.md/help/tags) | 标签不区分大小写，`/` 表示嵌套；标签搜索会匹配后代 | 必须区分语法层级与精确共现，不能用 `tag:ai` 搜索结果当作 `ai` 的精确文件集合 |
| [D3 force simulation](https://d3js.org/d3-force/simulation) | 支持停止自动计时后手动 tick，官方建议大图静态布局使用 Worker；模拟会修改传入节点 | 适合将受限规模布局移到后台；向布局传克隆对象，不能污染共享索引 |
| [D3 zoom](https://d3js.org/d3-zoom) | 可用于 SVG/Canvas，支持限制缩放和平移范围 | 可借用交互模块，仍需自行提供键盘按钮和关系表 |
| [Cytoscape.js](https://js.cytoscape.org/#introduction)及[性能说明](https://js.cytoscape.org/#performance) | 提供图模型、样式、布局和交互；官方说明边、标签和复杂样式会影响渲染性能 | 是功能完整的备选，但本阶段不需要完整图分析引擎，也不能假定引入库就解决性能问题 |
| [Sigma quickstart](https://www.sigmajs.org/get-started/quickstart/) | 使用 Graphology 图结构，并需要释放 WebGL 资源 | 适合评估更大规模图；当前有界视图不优先增加 WebGL 与独立图结构的维护面 |

## 3. 关系语义选择

| 候选关系 | 证据来源 | 第一阶段决定 |
| --- | --- | --- |
| 同篇笔记共现 | 精确标签的文件集合交集 | 默认关系；无向，可点击复核共同文件 |
| 直接父子层级 | 已有标签名称中的 `/` | 可选叠加；有向虚线，仅连接实际存在的直接父子，不推断共现 |
| 同义或语义相近 | AI、embedding 或用户维护词典 | 暂缓；缺乏可直接复核的确定性语义，容易被误解为合并授权 |
| 笔记链接投影 | 笔记链接加标签成员关系 | 暂缓；与共现是不同问题，首版不混合权重 |

共同文件数最容易解释，但偏向高频标签。详情同时给出 `J(A,B)=|F(A)∩F(B)|/|F(A)∪F(B)|` 作为交并比，首版仍按共同文件数排序；不把 Jaccard 称为“语义相似度”或模型置信度。

验证例子：四篇笔记分别具有 `{ai, python}`、`{ai, python, ai/tools}`、`{ai, ai/tools}`、`{python}`。三个节点文件数为 3、3、2；`ai—python` 为 2 / J=0.5，`ai—ai/tools` 为 2 / J=2/3，`python—ai/tools` 为 1 / J=1/4。`ai→ai/tools` 层级边独立存在，不能取代共现边。

## 4. 渲染与交付选择

| 路线 | 收益 | 成本和限制 | 结论 |
| --- | --- | --- | --- |
| 原生 SVG + D3 模块 + Worker 静态布局 | 复用当前 DOM/主题习惯，节点和边易与详情/测试关联，不要求 WebGL | 需实现选择、证据、可访问性和资源控制；大量 SVG 元素必须限量 | 首选；概览最多 200 节点、800 条可见边，数值为待测预算 |
| Cytoscape.js | 内建图操作、布局和交互较全 | 需要额外主题/可访问性适配；高级布局不一定避开 UI 线程 | 备选；只有首选的实际原型失败后再以证据修改设计 |
| Sigma + Graphology | 面向图渲染，有 WebGL 路线 | 增加图结构、GPU 生命周期和宿主兼容验证 | 留待确有大图需求时评估 |
| 修改 Obsidian 原生 Graph 内部 renderer | 视觉上贴近原生图 | 本调研未找到可据以承诺 tag-to-tag 注入的公开扩展契约 | 不采用；使用项目已有公开 ItemView 集成方式 |

选择 SVG 是基于限定规模、当前技术栈和可验证性作出的工程判断，**未测得**它比另两种方案更快或更小。实现前须记录锁定版本、传递依赖、许可证、`main.js` 体积增量和真实宿主表现。

## 5. 收敛的产品方案

独立打开先显示范围摘要和完整范围标签搜索；从标签详情进入时生成该标签的一跳邻域，最多包含根与 49 个邻居。范围概览由用户显式打开，选取最多 200 个真实标签，默认共同文件数阈值为 2。显示候选总数、显示数和省略原因；搜索不受概览前 N 限制。

比较详情提供共同/仅 A/仅 B、Jaccard 和双向覆盖率；也可独立选择没有共现的标签对。A=100、B=10、共同=10 时，A 覆盖率为 10%、B 为 100%，只能说明当前查询的使用范围包含，不能证明语义父子或应当合并。层级边仍只表达已有直接命名结构。

“带入整理”在现有工作台保留只读标签对/查询上下文，用户另选操作、方向、范围和写入位置，再进入既有审查与恢复流程。优先验证“找到关系 → 比较证据 → 整理审查 → 核对/撤销”的任务价值；不以图的美观或发布数量代替使用验证。保存查询、多视图和 AI 建议按产品 TODO 分阶段验证，3D、全库无上限布局和自动整理仍暂缓。

## 6. 必须在实现中回答的问题

- 内嵌 Worker 能否在 Obsidian 最低支持版本 1.8.7、验收时当前桌面版本、主窗口和弹出窗口离线工作？失败时能否切到分片计算的关系表？
- 快照序列化、统计、布局、渲染分别耗时多少？最大文件数之外，还必须测标签—文件成员数量和单文件高密度标签；只测节点数不充分。
- 200 节点 / 800 边和 10 秒任务期限能否满足下述性能门禁？不满足时保留未通过证据并调整方案，不能降低计数准确性或静默跳过笔记。
- 可访问关系表能否完整替代鼠标图交互？360px 窄窗口、深浅主题、缩放、退出/关闭任务是否可靠？
