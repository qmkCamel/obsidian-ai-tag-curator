# 标签管理工作台：产品设计

日期：2026-09-10。状态：待开发方案，不代表功能已上线。

## 1. 产品目标与用户

定位：不配置 AI 也能使用的标签管理工具；AI 是辅助判断，不是进入管理功能的前置条件。

主要用户是已有数百至数万篇笔记、同时使用 frontmatter 与正文标签的个人 Obsidian 用户。第一阶段优先桌面反复整理的工作流，窄窗口和键盘必须可用；移动端不以桌面截图代替验收。

| 用户任务 | 现在的障碍 | 本阶段交付 |
| --- | --- | --- |
| 找到某个标签及使用它的笔记 | 索引摘要只有部分标签，健康报告按问题组织 | 搜索、筛选、完整分页列表和相关笔记 |
| 已经决定改名或合并 | 必须先出现可执行健康问题 | 直接表达手动意图，仍然经过审查 |
| 只整理一个项目 | 不能统一排除模板、归档和关键标签 | 显式操作范围、全局排除与保护 |
| 检查插件刚改了什么 | 撤销分散在不同命令和结果页 | 可见历史、影响文件和冲突恢复 |
| 整理后立即核对效果 | 缓存可能滞后，统计口径不直观 | 明确新鲜度、刷新状态与文件数 |

不以标签总数减少作为成功指标。删除低频标签不一定改善知识库，用户主动保留的标签不能被视为失败。

## 2. 阶段边界

### 第一阶段：本 change 的交付范围

1. 标签列表、标签详情、相关笔记和选择状态。
2. 一个源标签的改名、多个源标签到一个目标的合并。
3. 操作范围选择、全局排除目录、保护标签。
4. 复用正文位置级审查、混合写入和恢复链路。
5. 历史列表、最近有效操作撤销、未完成操作处理。
6. 索引过期提示、有界且可取消的刷新、基本大列表性能。

### 第二阶段：只记录方向，不混入本阶段验收

- 命名规范预设、仅大小写修正、层级迁移、CSV 映射导入。
- “保留/忽略问题”、标准标签和别名规则的长期记忆。
- 选定笔记批量增加/移除标签；任何移除须单独设计风险与撤销。
- 真正的按文件增量索引；相关标签共现列表的价值验证。

不做后台静默改写、自动删除、全文重写、正则批处理、标签图谱、账号和云服务。不会因用户打开工作台而下载模型、发送笔记或测试 provider。

## 3. 信息架构

新增工作区页签“标签管理 / Tag manager”，通过命令与 ribbon 图标打开，复用已有实例。保留现有健康报告和推荐命令；工作台提供进入健康报告的明确入口，不把全部 AI 配置搬进工作台。

顶层只有两个页签：标签、历史。“范围与保护”是设置弹窗，不与内容页签混排。

宽窗口文字线框：

```text
标签管理                         索引：已过期       刷新图标
标签 | 历史                      范围与保护图标
搜索标签             来源筛选     排序       范围：项目 A
--------------------------------------------------------
选择  标签          文件数  来源 | ai/tools
 [ ]  ai/tools       12   F+B   | 重命名   合并到…
 [ ]  ai/reading      8   F     | 保护状态、来源文件数
 [ ]  work/status     6   B     | 笔记路径及来源，可打开
 ...                            | ...
上一页   1 / 20   下一页          | 上一页 / 下一页
--------------------------------------------------------
已选择 2 个标签                  合并到…       清除选择
```

此线框是结构说明，不是已验证视觉稿。正式 UI 使用文字“属性 / 正文”而非线框中的 F/B 缩写。

- 视图宽度不少于 900px 时列表与详情并排，列表至少 360px、详情至少 320px。
- 小于 900px 时使用列表/详情切换，详情有返回入口；历史详情同样处理。
- 360px 宽可完成核心浏览与确认；路径可换行，长标签允许断行；没有仅靠横向滚动才能触达的主要按钮。
- 工具按钮使用 Obsidian 内置图标与 tooltip；页签用原生语义，选择用 checkbox，来源/排序用 select；不使用装饰卡片、图表或营销说明。
- 搜索、页码、当前详情在同一个 workspace leaf 内保留；跨重载仅恢复页签和范围，不持久化搜索词、选择集合或审查正文上下文。

## 4. 标签列表与相关笔记

默认按范围内关联文件数降序、同值按标签稳定排序；每页 100 个标签，相关笔记每页 50 个。全选仅选择当前页可选条目，不隐式选择全库。

搜索采用标签名子串匹配，不解释正则、Obsidian 查询语法或自然语言。来源筛选为全部/属性/正文，含两种来源的文件在总文件数中只算一次。来源筛选只影响浏览，不偷偷改变改写来源；正文和属性的写入选择在审查中明确决定。

第一阶段不展示伪精确的“总出现次数”：现有 index count 不是正文 occurrence 计数。详情显示去重文件数、属性文件数、正文文件数；精确位置数只在按需读取审查后显示。不单独扫描整个库来填充数字。

点击标签打开精确标签的文件列表，而不是依赖可能包含子标签的 `tag:` 搜索结果充当精确证据。打开笔记走宿主文件接口；路径不作为 HTML 拼接。文件已删除显示不可打开，不自动寻找同名替代文件。

改变搜索/来源筛选/操作范围时清空标签选择并保留提示；分页不清空已选择条目，但工具栏必须显示跨页选择总数。范围变化不改变全局保护设置。

## 5. 手动改名与合并

### 5.1 表达意图

- 单选可重命名；多选可合并到一个现有或新标签；选择集合中含目标自身时从 source 中移除，source 为空则不产生计划。
- 不依赖健康问题或 AI 返回；用户的明确意图是来源，执行资格仍由本地验证决定。
- 仅处理精确标签。`project -> work` 不自动变更 `project/active`；涉及子标签时展示提示及子标签数量，但第一阶段没有“同时迁移子标签”开关。
- 输入允许去除一个前导 `#` 和首尾空白；不静默把非法空格改成连接符，不自动展平层级。支持中文、字母、数字、下划线、连字符与合法分段 `/`；纯数字、空层级、空输入拒绝。
- 沿用当前稳定改写子集，emoji/符号标签可浏览，无法安全执行时明确只读。目标的实际写入字面量必须在审查中展示；仅大小写不同的目标提示同一标签，留到后续规范化功能。
- 目标已存在时明确标记“合并”；属性中的目标避免新增重复项，正文中的已有目标和未选 token 原样保留。

### 5.2 范围与预览

默认浏览范围为全库；第一次进入改名/合并时必须经过范围确认，不自动记住上次“确认”。可选择包含目录及是否递归，并始终减去全局排除目录。不超过 200 个受影响文件；超过时阻断并要求缩小范围，不静默截断、不自动分批。

预览前通过有效索引确定候选文件，然后仅 hydrate 含 source 的文件。目标专属文件不进入计划。扫描中显示进度和取消；取消或晚到结果不写入也不重新打开弹窗。

审查复用现有结构：文件列表、属性前后值、正文行号和 token 差异、不可执行位置原因、逐项选择。保护项不可勾选。未选、不可执行或被规则跳过的范围分别统计，不能合并成一个“成功”数字。

二次确认显示目标、范围、将修改的文件/属性/正文位置数与部分处理说明。任何预览后内容、文件集合或策略变化都要求重新审查；不得点击后自动重新生成并直接应用。

### 5.3 写入、取消与结果

- 预览期可以自由取消；提交后禁用重复应用。
- 写入开始后第一版不提供“立即终止”按钮，避免留下任意半批；关闭视图只隐藏进度，任务与恢复状态继续由插件服务持有。
- 结果区分已应用、部分应用、冲突零写入、已回滚、需要恢复、已应用但索引刷新失败。
- 应用成功后在详情和历史中可见；索引失败只提供刷新，不提供重复应用原计划。

## 6. 范围与保护：两个不同概念

| 设置 | 生效位置 | 明确语义 |
| --- | --- | --- |
| 工作台包含目录/递归 | 本次浏览和手动操作 | 不改变当前笔记命令的目标；健康报告不共享临时浏览过滤，但仍遵守全局排除 |
| 全局排除目录 | 所有前向写入，以及 AI 内容读取范围 | 排除命中目录及子目录；不自动重定位重命名后的目录 |
| 保护标签 | 所有前向写入 | 不增加、不移除、不改名、不改其已有字面量；不禁止诊断和浏览 |

保护形式仅支持精确标签 `status/active` 或子树 `status/*`。子树规则保护 `status` 自身和后代，不保护 `status-old`。不提供任意 glob/正则，避免模糊匹配。

受保护的目标标签也不能作为新增或合并目标；用户需先明确解除保护，再重新审查。某篇笔记含受保护标签，不意味着其中其他标签完全不可改，但未选/受保护标签的字符串和顺序必须保留。

全局排除是阻止插件前向读取/改写的规则，不是历史清除工具：保存前告知现存索引片段需要失效重建，历史中的路径和最小 patch 仍保留用于恢复，不宣称抹除曾发送的数据。

撤销/恢复不是新的整理决策：即使事后排除了目录或保护了标签，仍可按原记录撤销或恢复，但需再次检查文件冲突，并在确认中列出当前规则例外。不允许顺带改变原操作以外的内容。

## 7. 历史与恢复

按记录顺序展示当前笔记推荐、文件夹批次、健康清理、手动改名/合并。主列表包括时间、来源、动作、文件数、状态；详情展示路径、标签变化，以及记录确实保存的正文 token 变化，不显示完整正文。

第一阶段只有全局最新未撤销操作可进入撤销预检，不按“同类型最新”绕过更晚操作。历史过滤条件不改变资格。先有 A 清理、后有 B 推荐时，不能从 A 卡片越过 B 撤销。缺失文件或后续编辑导致冲突时不跳过冲突项继续写其他文件。

已有 legacy 多文件 cleanup 缺少 V2 恢复信息，在新历史中只读并说明原因；旧清理回退入口同步走同一资格判断，不能保留绕过按钮。推荐、folder batch、V2 cleanup 根据其真实记录能力执行，不将旧记录升级为伪造的完整快照。

成功撤销后保留轻量历史摘要“已撤销”，删除用于继续写入的活动记录；保留标签前后值和路径，移除正文 patch。没有完整原值的旧记录明确注明“历史记录不含原始格式”。第一阶段无 redo、任意乱序撤销、历史记录删除按钮。

未完成操作优先置顶，提供原固定目标的恢复重试；其他新写入禁用，但只读浏览和历史查看仍可用。历史无法解析时不显示“没有历史”，而是恢复错误并阻止新写入。

## 8. 关键状态与可访问性

| 状态 | 可做 | 不可做 |
| --- | --- | --- |
| 无索引 | 配置范围、启动本地扫描、查看已有历史 | 显示虚构的零标签、运行手动改写 |
| 扫描中 | 浏览旧结果并看到旧标记、取消 | 把旧快照当作新预览依据 |
| 空库/筛选无结果 | 清除筛选或调整范围 | 混淆两种空态 |
| 索引过期/部分失败 | 查看旧统计、重试 | 新建或应用基于旧范围的计划 |
| 规则导致全跳过 | 查看命中原因、修改规则 | 写入空事务或声称已完成 |
| 恢复待处理 | 浏览、检查文件、重试恢复 | 新增另一笔写入 |

页签、列表 checkbox、翻页、动作和返回均可键盘操作；异步更新保留焦点，以 aria-live 简短报告完成/失败计数。关闭审查回到发起按钮；长路径与中英文标签不得遮挡按钮。颜色之外必须有文字或图标说明状态。

## 9. 验收与价值判断

以下是目标，不是已测得结果：

- 不设置 provider，在合成库中完成搜索、定位、改名/合并、检查历史、重载后撤销，全程零外部请求。
- 一次操作中未选标签、受保护标签、排除文件、未选正文逐字或按约定的属性原值保持不变。
- 1,000 标签的暖列表过滤 p95 小于 150ms；10,000 标签小于 300ms。固定机器、宿主版本、夹具、预热 5 次与正式 30 次测量，不包含输入 debounce。
- 10,000 篇合成笔记扫描可取消，取消后 250ms 内停止领取新工作；列表分页不生成与全库标签数等量的 DOM。
- 主路径无需打开设置寻找撤销；历史一次定位即可看到影响文件和执行来源。
- 真实测试库保存宽/窄、深/浅、键盘焦点、冲突、恢复关键态截图；最低支持版本与当前稳定版分别记录。

产品验证以 5 个真实使用者的指定整理任务为首轮样本，记录能否独立完成、哪一步犹豫、是否再次使用；这只是验证计划，不是市场需求证明。默认不增加遥测，反馈由用户主动提供，禁止自动上传 vault 路径或正文。

## 10. 已决策与后续决策

本方案选择原生 ItemView、精确标签操作、单目标合并、200 文件上限、保护优先、全局最近操作撤销。开发不需要再自行发明这些行为。

后续需由真实验收决定是否调高上限、是否进入移动端正式支持及是否扩展 emoji 改写。它们不阻塞第一阶段编码，但未完成对应证明时不得扩大宣传范围。
