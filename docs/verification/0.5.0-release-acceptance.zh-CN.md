# 0.5.0 发布验收

验收日期：2026-10-09。结论：本轮桌面发布门禁已通过，可以发布 0.5.0；不扩大为全平台或所有存储故障均通过的声明。

## 环境与隔离

- Apple M2 Pro / arm64，macOS 26.6.2（25G83）。
- 官方完整安装包：[Obsidian 1.8.7](https://github.com/obsidianmd/obsidian-releases/releases/download/v1.8.7/Obsidian-1.8.7.dmg)、[Obsidian 1.14.4](https://github.com/obsidianmd/obsidian-releases/releases/download/v1.14.4/Obsidian-1.14.4.dmg)。GitHub latest 在验收时为 1.14.4，发布时间为 2026-10-05。
- 两个独立应用副本、用户配置目录和合成 vault，分别使用本地 CDP 19287 / 19288；自动更新、Sync 和 Publish 关闭。未安装到生产库，未替换系统应用。
- 安装 `ai-tag-curator-dev@0.5.0`，仅开发插件 id/name 与正式 manifest 不同。`main.js` 和 `styles.css` 与正式构建哈希一致。无 API key，不调用 AI。
- 测试脚本限制 vault 实际路径、夹具标记和每次执行时的库路径；只有显式启用社区插件后才运行。1.14.4 初次尝试受 restricted mode 阻断，启用后重跑通过；另修正了测试按钮文案定位，未修改生产代码来绕过测试。

使用 `scripts/prepare-release-vault.mjs` 准备 `/tmp/tag-curator-release-*/<host>/vault`，在父目录放置内容为 `tag-curator-0.5.0` 的 `.release-fixture` 标记。启动对应官方应用副本，指定独立 `--user-data-dir` 和 `--remote-debugging-port`，并在该隔离配置启用社区插件。

设置 `OBSIDIAN_TEST_VAULT`、`OBSIDIAN_TEST_PORT`、`OBSIDIAN_TEST_VERSION` 和 `OBSIDIAN_TEST_ASSETS` 后，依次执行：

```bash
node tests/verification/host-workbench.mjs --buildready
node tests/verification/host-workbench.mjs --installed --recovery-prepare
# 完整退出并重新启动同一隔离应用与配置，再继续。
node tests/verification/host-workbench.mjs --installed --recovery-resume
```

ASSETS 必须位于 `docs/verification/assets/` 内；每轮使用新目录，避免覆盖历史证据。故障注入只允许用于一次性合成 vault。

- 本轮不重测外部 AI provider 或下载端侧模型；AI 保持可选，本地管理没有网络依赖。
- 历史宽窄/深浅主题合成浏览器矩阵与本轮真实宿主结果分开，不宣称重新执行了全部历史视觉矩阵。
